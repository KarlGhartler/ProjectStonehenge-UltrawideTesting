# Port risks per subsystem

What can make the port behave differently from the original, and how each risk is handled. Coverage numbers: `coverage.md`. Open questions: `../open-questions.md`. Decisions: `../decisions/`.

| Subsystem | Risk | Mitigation | Details |
|---|---|---|---|
| Core / random | Five random sources must be reproduced exactly, including the call order inside a frame. The random-table cursor reset per frame limits the damage of a mistake to one frame, but `rand` carries over across frames (radio, visuals). | Implement newlib `rand`, the table, the VU0 R register, the effect LCG and the sound LFSR bit-exactly. Replay tests against PCSX2 recordings. | `../game/random.md` |
| Core / memory | The work heap is 98.4 % full in mission 1 and `WorkHeapAlloc` returns 0 without callers checking. The records page makes heap offsets depend on the frame count. | Guest memory with the exact PS2 heap base and size (ADR-001); exact struct sizes; exact frame counter. | `../game/memory.md`, ADR-001 |
| Timing | Game logic is frame-locked at 59.94 Hz; in-menu movies are paced by timer 0 (280 H-blanks); the draw-list build changes game state (`DrawHud` radar mode) and consumes random numbers. | Fixed step with accumulator; draw-list build exactly once per step; extra presented frames re-use recorded lists (ADR-002). | `../game/threads-timing.md`, ADR-002 |
| SDK layer (skeleton) | `src/sce/` currently uses host libm for `sinf`/`cosf`/`atan2f`/`sqrtf` and host float math for the libvu0 matrix helpers (`sceVu0RotMatrix*`, `InversMatrix`, `ApplyMatrix`). Neither is bit-exact with newlib or the VU0 macro code (`_sceVu0ecossin` polynomial). None of them is reached on the boot path. | Translate the newlib and libvu0 algorithms from the ELF before the first gameplay code that calls them; test against captured values. | `src/sce/libc.cpp`, `src/sce/libgraph.cpp` |
| Core / VU0 | Macro-mode code reads VU0 MAC flags (`cfc2`) a few cycles after vector ops; on hardware the flag pipeline delay returns the flags of an earlier op. PCSX2 does not model this and patches 3 sites (projection 0x0010FFB8, collision 0x0017C020 / 0x0017C688). A naive translation would change collision results. | Translate the hardware result at each `cfc2` flag read; RAM comparison with PCSX2 states found the patched sites. | `validation.md` B-2 |
| Flight | Double-precision soft-float damping and libm `sinf`/`cosf` results must match bit for bit. | `ee_math.h` with exact soft-float steps and translated libm algorithms. Behaviour tests with captured values. | `../subsystems/flight.md` |
| AI / weapons | Pool slot rules (ring overwrites, 64-bit occupancy masks) and the one-frame damage delay. Replays reference slot numbers. | Translate the pools literally. Never replace them with dynamic containers. | `../subsystems/weapons.md`, `../subsystems/ai.md` |
| Effects | They run in the simulation step and read the random table, so they **cannot be reduced, skipped or reordered**. 281 bodies are not read yet. | Translate them literally. An "effects quality" option would change gameplay randomness, so it is not possible as a baseline feature. | `../subsystems/effects.md` |
| Rendering | About 233 packet-writing functions and 5 VU1 programs. Collision depends on model packet data. Off-screen passes use fixed GS pages and sizes. The VU1 3D path is not yet characterised (GS dumps needed). | ADR-003 (VU1 HLE, GS replay). Keep packet data as data. Any resolution scaling must scale the shadow and half-resolution passes consistently. | `../subsystems/rendering.md`, `../subsystems/vu-programs.md`, ADR-003 |
| Sequence (cutscenes) | VU0 micro-mode skinning plus direct DMA channel control. | VU0 micro interpreter or a verified rewrite of the 9 entry points (PCSX2 reference data). | `../subsystems/rendering.md`, `../subsystems/vu-programs.md` |
| Frontend | Records-page heap allocation depends on the frame count; the game has its own anamorphic 16:9 mode. | Exact heap and frame counter; output pass presents 16:9 when SCREEN RATIO is on (ADR-006). | `../subsystems/frontend.md` |
| Save | Byte-identical saves need the exact image build, checksum, clamp and write order; the 3-read card debounce and frame timeouts are game logic. | Translate the save page and the `sceMc*` step machines; `src/sce/` on the PCSX2 folder layout. Test against PCSX2 folder cards. | `../subsystems/save.md`, `../formats/SAVE.md` |
| Sound / radio | The radio depends on `rand`; two-voice scheduling and 600-frame repeat blocks; SOUND/VAG first replies must match or boot hangs. | Keep the radio in the simulation order. The audio backend reproduces the SOUND/VAG replies (ADR-004). | `../subsystems/sound.md`, `../subsystems/iop-sound.md` |
| Movie | T0-paced in-menu movies; MPEG-2 decoding; SMV PCM block layout unconfirmed. | Decoder dependency decided at the skeleton phase; PCSX2 capture for the PCM layout. | `../formats/SMV.md`, `../subsystems/iop-sound.md` |
| HDD | Unreachable code that still has to be translated; SDK stubs needed. | Logging stubs per the dead-code rule. | `../subsystems/save.md`, `dead-code.md` |
| Data formats | DATA 291–332 and BD 2 have no loader; terrain and VIF vertex layouts only partly decoded. | PCSX2 checks. The port reads everything from the ISO at runtime anyway. | `../formats/CDP.md`, `../formats/MODEL.md` |
| Ghidra database | The ghidra-mcp plugin silently re-adds Hungarian prefixes to struct field names (`MainContext`, `CdFileEntry`); `save_program` can hang. | Rename struct fields by hand in the Structure Editor; save from the Ghidra UI. | `../decisions/naming-convention.md` |
