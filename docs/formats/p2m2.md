# PCSX2 input recording (`.p2m2`, file version 1)

Not a game format: the input-recording file written by **PCSX2 2.8.2** (our reference version). The port reads it in the debug layer to replay PCSX2 input (`../port/validation-strategy.md` §3). It holds only pad bytes, no game data.

Source (read, not copied): PCSX2 v2.8.2, `pcsx2/Recording/InputRecordingFile.{h,cpp}`, `PadData.cpp`, `InputRecording.cpp`, `VMManager.cpp` (`PollInputOnCPUThread`). Confidence: **confirmed from source**; to be checked against one real file in the first gameplay slice.

## Layout

All integers little-endian. No padding (the header struct holds only `u8`/`char`).

| Offset | Size | Field | Notes |
|---|---|---|---|
| 0x000 | 1 | `file_version` | must be 1 (PCSX2 rejects other values) |
| 0x001 | 50 | `emulator_version` | `"PCSX2-<git rev>"`, NUL-padded |
| 0x033 | 255 | `author` | NUL-padded |
| 0x132 | 255 | `game_name` | `VMManager::GetTitle()`; PCSX2 only warns on a mismatch |
| 0x231 | 4 | `total_frames` (u32) | updated while recording |
| 0x235 | 4 | `undo_count` (u32) | re-records |
| 0x239 | 1 | `from_savestate` (bool) | 1: starts by loading `<file>_SaveState.p2s`; 0: starts with a VM reset (power-on) |
| 0x23A | 36 × n | frame records | frame `f` at `0x23A + 36·f` |

Frame record = port 0 (18 bytes), then port 1 (18 bytes). Multitap slots are not stored.

## The 18 pad bytes

They are **byte for byte the DualShock 2 data bytes 2–19 of the `scePadRead` buffer** (buttons active-low, then analog sticks, then pressures), so the port can copy them directly into its `scePadRead` answer (`src/sce/libpad.cpp`):

| Byte | Content | `scePadRead` byte |
|---|---|---|
| 0 | buttons: bit 0 Select, 1 L3, 2 R3, 3 Start, 4 Up, 5 Right, 6 Down, 7 Left (0 = pressed) | 2 |
| 1 | buttons: bit 0 L2, 1 R2, 2 L1, 3 R1, 4 Triangle, 5 Circle, 6 Cross, 7 Square (0 = pressed) | 3 |
| 2, 3 | right stick X, Y | 4, 5 |
| 4, 5 | left stick X, Y | 6, 7 |
| 6–9 | pressure Right, Left, Up, Down | 8–11 |
| 10–13 | pressure Triangle, Circle, Cross, Square | 12–15 |
| 14–17 | pressure L1, R1, L2, R2 | 16–19 |

Note: `PadData(port, slot, data)` in PCSX2 also reads in this order (`right` = byte 6, `left` = byte 7, …), confirming the table.

## Frame numbering

- One frame record per **vsync**: `VMManager::Internal::PollInputOnCPUThread` (called after vsync start, before the counter's vsync end) increments the recording frame counter, then reads/writes the pad data of the new frame and overrides the emulated pad. AC04 runs one game step per vsync (59.94 Hz), so one record ≈ one game step.
- The counter starts at 0 when the recording starts. A power-on recording resets the VM, so its frame numbers include the BIOS and the boot; a from-savestate recording counts from the state.
- The override sets the **emulated controller**. The game sees it through libpad/SIO2 on the IOP, i.e. with the PS2's pad latency. The port answers `scePadRead` directly, so the offset between "record `f`" and "the step whose `scePadRead` returns it" must be calibrated once (`../port/validation-strategy.md` §3.2).
- PCSX2 needs **Settings → Advanced → Enable Recording Tools** for the recording menu.
